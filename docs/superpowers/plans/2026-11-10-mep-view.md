# 설비 보기 + 아일랜드 싱크 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 장 배치를 따라 급수 · 배수 · 전기 · 가스 · 배기 · 난방 설비를 자동으로 잡아 평면도와 3D(투시) 에 보여 주고, 싱크를 아일랜드로 옮길 수 있게 한다.

**Architecture:** 계산은 순수 함수 하나(`src/mep.ts` `mepOf(d, c)` — flow.ts 와 같은 방식)가 맡고, 평면도(`plan2d.ts`)와 3D(`mep3d.ts` → `scene.ts setMep`)는 그 결과만 그린다. 인입점 · 일반 콘센트의 사용자 자리는 `Design.mep` 에 저장한다(저장 · 불러오기 · 되돌리기에 그대로 실림). 아일랜드 싱크는 기존 「아일랜드 쿡탑」(`fix.hob.island`) 방식을 싱크 · 식기세척기로 넓힌다.

**Tech Stack:** TypeScript · Vite · three r186 WebGPU · SVG. 시험은 `npx vite-node tools/probe-*.ts` 요약 줄 + `tools/check.mjs`(npm run check).

**Spec:** `docs/superpowers/specs/2026-11-09-mep-view-design.md` (승인 2026-11-10)

## Global Constraints

- 단위 mm, 평면 좌표 x 오른쪽 · z 아래(plan.ts 머리말), 높이 y 는 바닥에서 위로(바닥 속 = 음수).
- 화면 문구는 한국어. 수치는 「가정」 · 「확인 필요」 · 「권장」으로만 — 법규처럼 단정하지 않는다(spec 3 · 4절).
- 확인 못 한 기준(spec 3절 목록)은 상수 `MEP_ASSUME` 한 곳에 「가정」 주석과 함께. 판정 문구에 「가정」을 붙인다.
- 난방은 개별 보일러만(지역난방 선택지 없음). 일반 콘센트는 자동으로 깔지 않는다(사용자가 놓음).
- 필요할 때만 그리기를 깨지 않는다 — 설비 보기를 꺼 두면 3D 비용 0, 켜도 가만히 있으면 그리지 않는다(`invalidate` 만).
- 공유 형상 · 재질은 `shared()` 표시, 지울 땐 `disposeTree` — 반투명으로 바꾼 장 · 방은 놓기 전에 원래 재질로 되돌린다(src/dispose.ts 규칙).
- 3D 설비 보기는 실시간(raster) 모드에서만. 다른 모드로 가면 끈다.
- 커밋 · 푸시는 사용자 확인 뒤에만(사용자 규칙) — 태스크마다 커밋하지 않는다. 끝나면 v0.0.6 로 묶어 묻는다.
- 헤드리스 크롬 시험 스크립트는 끝날 때 임시 프로필을 지운다. Playwright MCP 브라우저는 건드리지 않는다.

## Review Focus

1. 방을 줄이거나 다용도실을 빼서 고정한 인입점 자리가 없어짐 → 가장 가까운 알맞은 벽 · 바닥에 붙어 보여야 하고 사라지거나 방 밖에 뜨면 안 된다. (Task 3 probe: 방 밖 고정점 · 다용도실 뺀 뒤 고정점)
2. 아일랜드 싱크를 둔 뒤 아일랜드를 끌거나 돌림 → 싱크 · 식세가 아일랜드에 붙어 따라오고 설비 경로도 다시 잡혀야 한다. (Task 1 probe: pos · rot 바꾼 아일랜드)
3. 설비 3D 를 켠 채 장 · 옵션을 바꿔 부엌을 다시 만듦 → 반투명 재질이 새 부엌에 다시 입혀지고, 옛 재질 누수 · 「destroyed buffer」 오류가 없어야 한다. (Task 6 헤드리스: 켠 채 다시 만들기 5번 + 콘솔 검사)
4. 설비를 켠 채 실사 모드로 바꿈 → 설비가 꺼지고 장 · 방 재질이 원래대로. (Task 6 헤드리스)
5. 예전 설계 파일(mep 없음) · 아일랜드를 끈 설계에 `fix.sink.island` 가 남음 → 기본 인입점으로 그려지고, 싱크는 벽 자동 배치로 돌아간다. (Task 1 · 3 probe)

- 정한 값(spec 5.2 · 5.3 · 5.4 · 5.7):
  - 붙일 벽 = 부엌 벽(트인 벽은 날개벽 자리만, 다용도실 · 서브주방 · 팬트리 입구 폭은 뺌) + 벽 너머 공간의 안쪽 세 벽(room3d `sideRoom`: 안쪽 t ∈ [o.t−300, o.t+o.w+300], u ∈ [−150−depth, −150]). 바닥 = 부엌 사각형 + 그 공간 바닥.
  - 기본 인입점: 배수구 · 급수 = 싱크 벽 아래(벽 싱크는 그 뒤 u 80, 아일랜드 싱크는 가장 가까운 부엌 벽), y = floorY. 분배기 = 싱크장 밑(아일랜드 싱크면 배수구에서 가장 가까운 벽 하부장 밑), y 60. 분전반 = 날개벽 → 트인 쪽과 맞닿은 옆 벽 끝(300 안쪽) → 정면 맞은편 벽, y panelY. 가스 = 다용도실 맞은편 벽(창 옆) → 쿡탑 벽(아일랜드 쿡탑이면 가장 가까운 벽), y gasY. 덕트 = 쿡탑 벽 쿡탑 위(아일랜드면 가장 가까운 벽), y = 천장 − ceilGap. 보일러 = 다용도실 옆 벽 → 가스 인입 옆 600, y boilerY.
  - 고정 인입점(`d.mep.inlets`)은 계산할 때마다 `snapWall` · `snapFloor` 로 붙인다(설계 값은 그대로 둠 — 방이 다시 커지면 제자리). 높이는 [100, 천장 − 100].
  - 경로: 벽 따라가기 = 부엌 둘레(뒷벽 시작 0 → 시계 방향)에서 트인 벽의 날개벽 사이 구간을 지나지 않는 쪽, 벽 면에서 종류별 inset(전기 20 + 15·k, 냉수 40, 온수 70, 배수 100, 가스 40, 난방 공급 130 · 환수 160, 배기 120). 벽 너머 공간 기기 ↔ 부엌은 입구 가운데로 지난다. 아일랜드로는 바닥 속(floorY)으로 — 가까운 벽까지 곧게 간 뒤 벽을 따라.
  - 높이: 급수 · 난방 lowY(하부장 뒤), 배수 = 트랩 450 → floorY, 전기 = 천장 − ceilGap 로 가다 내려옴(아일랜드 · 바닥 콘센트는 벽 아래로 내려 바닥 속), 가스 gasY, 배기 = 후드 위 → 천장 − ceilGap(후드일체형 인덕션은 쿡탑 → 걸레받이 높이 60 → 벽 → 위로).
  - 기기: 싱크(냉 · 온 → 수전, 트랩 → 배수구), 식세(냉수 분기 · 트랩으로 배수 · 콘센트 「식세 16A」 싱크장 안 dedicated), 쿡탑(이름에 「가스」 → 가스 중간밸브 y 500, 그 밖 → dedicated 「인덕션 전용」 y 300; 「후드일체형」 → 배기도 쿡탑에서), 오븐(dedicated), 후드(배기 + 후드장 콘센트), 냉장고(general y 300), 아일랜드(팝업 콘센트 늘), 일반 콘센트(`d.mep.outlets`), 분배기(보일러 공급 · 환수 + 방 쪽 바닥 난방관 짧게 3줄 + 구동기 전원), 보일러(가스 · 온수 출발). 다용도실 = 세탁기(냉 · 온 · 배수 · 전기) · 건조기(전기) · 세탁 싱크(냉 · 온 · 배수) — room3d 와 같은 자리. 서브주방 = 싱크(급배수) · 쿡탑(부엌 쿡탑 종류를 따름) · 후드(배기 · 전기). 팬트리 = 콘센트 · 조명.
